## Intentional safety differences

The old `tool_choice: "none"` → `"auto"` workaround is not retained. A loaded search result does not override an explicit no-tool request. Normal permitted discovery → invocation remains supported, including discovered definitions marked deferred.

Also excluded:

- Broad implicit injection from ordinary converters, empty requests, arbitrary nested output or bare history markers.
- Shim ownership guessed from a public function schema or application-owned `tool_search` name.
- Namespace-wide/unsupported Anthropic selectors silently degraded to `auto`. Unsupported restrictions produce an explicit error; exact named choices and supported allowed sets retain their restriction.
- Silent conversion of server-executed search to client execution. The compatibility conversion explicitly rejects unsupported server search.
- New native compatibility on official providers, GrokBuild, compact endpoints, compaction turns or saved tool/choice overrides. The legacy xAI namespace-only route remains separate.

A saved `tools` replacement owns its returned function identities on all transports. A choice-only xAI override still preserves the original flattened namespace identities while suppressing new injection.

Streams preserve stable `tsc_` IDs, split UTF-8/arguments, late argument ordering, SSE IDs/retry/comments/event fields and unknown framing fields. xAI integer normalization precedes item-type restoration. Compaction retains official #7976: definitions may remain for referenced history, while `tool_choice: "none"` prevents new calls.

Loaded-set semantics are documented in the [OpenAI ToolSearch guide](https://developers.openai.com/api/docs/guides/tools-tool-search).

## Private-cache removal and residual-state limits

The follow-up removes only the cache-specific additions originally introduced in `81b295138a5fdc100096a2d4d2ebdb2ed6875fa4`, plus replaces the private-cache mode fixture with a public-catalog/no-private-storage regression. The retained catalog and per-model reasoning code precedes that commit and remains intact. `codex_client_catalog::observe(store)` still observes the actual public catalog even after a partially failed write.

Removed dependencies are `rusty-leveldb`, `crc32c`, `errno 0.2.8`, `errno-dragonfly`, `fs2`, `integer-encoding` and `snap`. The existing `errno 0.3.14`, `once_cell`, official model discovery/cache and SQLite application database remain.

This change does **not** undo old runtime side effects. A previous 4.0.4 or `cdd628f7` build may have left injected model IDs, ownership markers or future Statsig timestamps in the installed Desktop cache. The new candidate neither reads nor cleans up that storage. Switching to an official provider will no longer release those old private-cache pins.

The new fixture exercises direct → proxy → direct → official transitions using an isolated home, once without any private-storage directory and once with an uninterpreted synthetic sentinel. It verifies public catalog JSON publication and `visibility: "list"`, no directory creation, and unchanged sentinel bytes. It does not launch Desktop and cannot prove the current picker consumes that catalog independently of historical cache state.

Before any real claim of cache-independent Desktop support, Windows acceptance must exclude historical private-cache effects through a separately coordinated, reversible isolated profile or backup-backed isolation plan. No real cache clearing/isolation operation is authorized or performed by this source change. If custom models disappear without the old state, report the public-catalog limitation rather than silently restoring private-cache writes or relaxing tool permissions.

## Remaining Windows acceptance

Run only the platform/real-client checks not established by the cloud tests; do not repeat the unchanged frontend suite or all Linux unit tests on the user's computer.

1. Build the Windows candidate and run Windows-only npm repair/launcher/filesystem tests. Cache-layout tests have been removed with the private subsystem.
2. Record installed CC Switch and Codex Desktop versions, selected provider, catalogs and rollback inputs. Agree on a reversible test profile or backup-backed isolation plan before touching any existing cache. This plan and its operations are separate from the current authorization.
3. Exclude all historical Statsig/LevelDB injections and future timestamps from the test context. A picker that works only with the old cache does not prove public-catalog support. With a genuinely unaffected test context, check custom model visibility, selection, explicit reasoning levels, provider/official switching, direct/proxy transitions, external catalogs and restart behavior.
4. Use already-authorized read-only deferred tools through Chat, Anthropic and native Responses to validate actual client behavior: streaming/failover, loaded schemas and namespaced invocation. Verify denied/no-tool/allowed-set/forced-tool requests stay restricted and saved tool overrides keep their identities.
5. Verify provider/config/database rollback and the absence of unintended changes to the existing installation. Stop and report any cache-independent picker failure; do not reintroduce LevelDB or `none` → `auto` as a workaround.
6. Only after the remaining checks pass does the user replace their installed 4.0.4 build. This task does not install or overwrite it. Official updates can replace local custom patches.

This is a cloud-validated source candidate, not an installed upgrade or a claim of lossless current-Desktop compatibility. Removing private-cache code does not clear historical private-cache state.
